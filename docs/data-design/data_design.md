# 数据模块合同

> 本文拥有“数据源 / 研究资料 / 配置”三个页面的用户职责、主动摄取调度、操作生命周期和失败语义。Source、Evidence、Wiki、Memory、日志与恢复的内部合同以 [`../knowledge-design/wiki.md`](../knowledge-design/wiki.md) 为准；资料到位之后的复核节奏以 [`../research-design/research_design.md`](../research-design/research_design.md) 为准。

## 1. Responsibility

数据模块聚合并管理行情、财务、行业、公告、研报和用户资料等分析输入，以及高级规则。它是利润、估值和先行指标分析的支撑层，不把“资料整理完成”当作用户最终价值。

本模块负责：

- 查看和配置真实外部数据通道；
- 按既定节奏主动获取关注对象的新资料；
- 管理用户历史上传的文件、URL 和粘贴资料；
- 提供资料 CRUD 的影响预览、二次确认和恢复入口；
- 管理 Schema、研究 Skills、标签和时效规则；
- 通过全局“变更记录”恢复已删除的研究档案、资料或配置；
- 展示连接、解析、更新和失败状态。

本模块不负责：

- 展示个股 Wiki、行业 Wiki 或对象当前报告；
- 将 `Vibe-Research`、`Daily Stock Analysis`、`llm-wiki` 或 Pi 显示为业务数据源；
- 要求普通用户理解 Evidence 编译、Git 或 commit；
- 保存行情 tick 或建立聊天历史。

## 2. Information architecture

数据页固定包含三个二级 Tab：

```text
数据源 | 研究资料 | 配置
```

### 2.1 数据源

面向真实信息通道、连接和数据状态。用户从通道卡进入配置或故障处理。

### 2.2 研究资料

只展示用户历史上传的文件、URL 和粘贴文本。公司 / 个股 Wiki、行业 Wiki、系统自动事实和内部关系不在此页面出现。

### 2.3 配置

使用卡片进入 Schema、研究 Skills、标签、时效规则和变更记录。Schema 属于默认折叠的高级能力。

## 3. 数据通道与主动摄取

### 3.1 通道看板

数据源按用户可理解的业务通道组织，例如：

- 官方披露；
- 财务与量化数据；
- 研究报告；
- 调研纪要；
- 资讯舆情；
- 行业与产业链数据；
- 市场传闻。

每张通道卡至少表达：

- 通道名称和用途；
- 是否已配置 / 可用；
- 最近成功获取时间；
- 当前失败或降级状态；
- 进入配置或重试的动作。

`Vibe-Research` 是后台能力提供者，不是卡片名称。未来增加港美股等市场时，应优先通过通道接入和配置扩展，而不是增加另一套产品信息架构。

### 3.2 主动摄取调度

用户不需要手动去取新消息。系统对已加入研究的对象主动摄取，未加入的对象不建立后台任务。

| 节奏 | 内容 | 说明 |
|---|---|---|
| 按需 | 行情、日 K、估值和实时行业指标 | 页面打开或分析需要时读取，不持久化 |
| 每日 | 关注对象的公告、新闻和研报 | 增量获取，已获取的不重复登记 |
| 披露窗口加密 | 定期报告 | 进入某报告期的披露窗口后提高检查频率，直到该对象的报告到位或披露截止日与宽限期过去 |

摄取到的新资料自动登记为 Source 并按 [`../knowledge-design/wiki.md`](../knowledge-design/wiki.md) 的合同归档，不逐条要求用户确认，但必须记录日志并形成 checkpoint。

职责边界：本模块拥有「系统什么时候去取、取什么、取失败怎么办」；资料到位之后是否触发复核、触发轻复核还是深复核，由 [`../research-design/research_design.md`](../research-design/research_design.md) 拥有。本模块不判断资料是否改变了研究结论。

单个通道失败只影响该通道：通道卡显示失败、最后成功时间和重试入口，其余通道继续按各自节奏工作。披露窗口内反复取不到定期报告时，本模块只如实报告「未获取到」，由研究模块决定标记证据过时和知识缺口。

## 4. Research materials

### 4.1 Supported inputs

用户可以：

- 上传本地文件；
- 添加 URL；
- 粘贴文本；
- 从对象页添加并默认关联当前对象；
- 在本页批量导入。

系统自动识别候选个股和行业。识别明确时直接进入摄取；存在歧义时展示候选并要求用户选择。

### 4.2 List and detail

资料列表至少表达：

- 标题和输入类型；
- 来源 / 发布者；
- 上传时间、发布时间和数据截至时间；
- 关联研究对象；
- 当前解析或更新状态；
- 查看、编辑、删除、变更记录和恢复入口。

资料详情可以展示原文、基本信息、关联对象、已产生的证据摘要和影响范围，但不展开完整 Wiki 管理界面。

### 4.3 CRUD lifecycle

新增资料后自动进入 Evidence 提取和 Wiki 维护，不逐事实审批。

编辑或删除前执行：

```text
计算受影响对象、证据和当前报告
→ 展示结构化影响摘要
→ 用户二次确认
→ 执行知识事务
→ 返回更新、待复核或失败结果
```

用户取消时不产生修改。执行失败时保留原资料和最后成功研究结果。Raw 的日常摄取和纠错不原地覆盖；用户在本页明确删除原始资料是唯一删除例外，当前树移除后仍由仓库级变更日志和 Git checkpoint 提供恢复。删除研究档案只解除资料关联，不删除这里的原始资料。

### 4.4 Change and recovery

“变更记录”使用产品语言展示时间、动作和影响范围，不出现 Git hash、分支或命令。“恢复”先预览影响并二次确认；恢复本身是新的知识事务。

## 5. Configuration dashboard

配置页使用卡片入口，不把所有高级字段直接铺在首页。

### 5.1 Schema

Schema 配置默认折叠并标为高级能力。用户可以查看和调整：

- Wiki 页面类型和组织约定；
- 对象分析框架和核心问题；
- 交叉引用与冲突处理规则；
- 数据时效窗口；
- 触发待复核的关键阈值。

Schema 用于约束 Agent 怎样维护知识，不预先枚举各行业必填字段。对象身份、来源、原文定位、FCISU 和数据时间等证据底线不可删除。

Agent 在正常摄取和分析中新增可复用页面类型或维护规则时，可以随知识更新一并演化 Schema，记录原因并形成 checkpoint，不逐次打断用户。用户主动编辑 Schema，或删除、重命名、迁移已有结构等可能重算现有知识的变更，必须通过影响预览和二次确认。

### 5.2 Research Skills

“研究 Skills”支持：

- 查看内置和已导入 Skills；
- 导入 Pi Skill / Pi Package 提供的方法；
- 启用或停用；
- 声明适用对象、行业或分析环节；
- 查看方法说明和证据要求。

首版方法结构为默认主线和少量通用方法，不要求按行业预建 Skill。用户 Skill 可以补充或替换指定环节，但不能绕过证据锚点、FCISU、时间和缺口要求。

首版不提供 Skill 商店、协作发布、分支或产品版本号。本地 Git 只承担审计和恢复。

### 5.3 Tags

普通标签是个股和行业的轻量属性，用于研究列表筛选和临时定位。个股的“关注 / 跟踪 / 持有”是加入或维护关注关系时直接选择的内置标签，不由 Schema 或本配置卡管理。两类标签都不创建研究池、独立股票池、专题或全局报告范围。

### 5.4 Freshness

时效规则按数据性质提供默认窗口，用户可在高级配置中调整。调整后系统展示影响对象并重新推导新鲜、趋旧和过时状态。

### 5.5 Change history

“变更记录”是全局恢复入口，按业务时间线展示动作、对象和影响范围，不出现 Git、commit、hash 或分支。它用于恢复已经删除、因对象不存在而无法从原页面进入的研究档案，也可以承接资料和配置的恢复预览。

恢复前再次说明将恢复的研究内容、关系和关注状态；用户确认后执行新的恢复事务。

## 6. Structured actions

数据页的直接表单和助手触发动作最终调用同一组确定性领域命令。

- 查询、预览和解析状态不需要持久修改确认；
- 新增、编辑、删除、恢复、用户主动修改 Schema 和 Skill 适用范围修改需要结构化输入；
- 删除、恢复、破坏性 Schema 变更和持续研究行为等有明显影响的动作需要二次确认；
- Agent 随正常知识维护进行的非破坏性 Schema 演化不逐次确认，但必须记录原因、影响和 checkpoint；
- Agent 只能提出并填充结构化动作，不能直接绕过前端确认写入。

已经启用的后台自动摄取和更新不逐次弹窗，但必须记录日志并形成 checkpoint。

## 7. Local metadata boundary

客户端 SQLite 至少保存：

- 个股、行业、关注关系及其“关注 / 跟踪 / 持有”标签元数据；
- 数据源连接和状态元数据；
- 用户上传资料索引；
- 初始化、复核和失败恢复事件；
- 前端查询所需的派生状态。

Purpose、Schema、Raw、Wiki、Memory、稳定的通用 Skills 和 `wiki/log.md` 等确定性知识文件进入本地知识仓库并由 Git 管理。接口缓存、tick 和临时解析产物不进入知识仓库。

具体表、字段、migration 和命令 payload 由实施 Task 定义；不得将同一事实同时交给 SQLite 和文件仓库作为权威写入者。

## 8. Capability reuse

- `Vibe-Research` 提供行情、财务、估值、公告、行业和资讯等主要数据工具；
- `Daily Stock Analysis` 提供方法和数据降级参考；
- `llm-wiki` 提供摄取、Schema、关系、日志和检查参考；
- Pi + Extensions 提供 Agent、Tools、Skills 和结构化动作运行基础。

这些名称不进入普通用户的信息架构。

## 9. Failure semantics

| Failure | User-visible behavior | Preserved state |
|---|---|---|
| 数据源不可用 | 通道卡显示失败、最后成功时间和重试 | 其他通道继续可用 |
| 披露窗口内未取到定期报告 | 通道卡如实显示未获取到，不生成占位报告 | 已有资料与最后成功研究结果 |
| 用户资料解析失败 | 资料保留并显示失败原因，可重试或删除 | 原始上传内容 |
| 对象识别歧义 | 展示候选并等待选择 | 上传草稿 |
| Evidence / Wiki 更新失败 | 标记更新失败并可重试 | 最后成功知识和报告 |
| CRUD 事务失败 | 明确“未生效” | 原资料和研究状态 |
| Git checkpoint 失败 | 整个持久修改视为失败 | 事务前状态 |
| Schema 重算失败 | 不启用新规则，展示影响和重试 | 原 Schema 与知识 |
| Skill 无法加载 | 停用该 Skill 并说明原因 | 默认研究主线 |

## 10. Public interfaces

数据模块至少提供：

- 列出和配置业务数据通道；
- 添加文件、URL 和文本；
- 列出、查看、编辑和删除用户资料；
- 预览资料或配置修改影响；
- 确认并执行知识事务；
- 查询全局变更记录、预览影响并发起研究档案或资料恢复；
- 管理 Schema、Skills、标签和时效规则；
- 返回解析、更新、待复核和失败状态。

具体接口形状由实施 Task 定义，但所有修改必须复用 Wiki 模块的原子事务和恢复合同。

## 11. Business validation

首版验收必须证明：

- 三个 Tab 的职责清楚，“研究资料”中看不到个股 / 行业 Wiki；
- 数据源卡表达真实通道、最近成功时间和局部失败；
- 关注对象的公告、新闻和研报无需用户手动触发即可增量到位，且不重复登记；
- 定期报告在披露窗口内提高检查频率，未取到时如实报告而不伪造结果；
- 文件、URL 和粘贴文本均可新增，批量导入能处理对象识别歧义；
- 编辑和删除前能够看到影响并二次确认；
- 事务失败不会留下资料与研究知识不一致的半成品；
- 用户能从配置页的“变更记录”恢复已经删除的研究档案或资料，但无需理解 Git；
- Schema 高级配置保护证据底线并允许对象结构逐步演化；
- Pi Skills 可以导入、启停和声明适用范围；没有行业专用 Skill 也能使用默认主线和通用方法。
