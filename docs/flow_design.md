# Vibe-Finance 首版跨页面业务流程

> 本文是 Vibe-Finance 跨页面用户旅程、页面职责边界、对象生命周期和整体验收的唯一 Owner。人类确认边界以 [`human-checklist.md`](../human-checklist.md) 为准。
>
> 本文不复述模块合同的内部细节。行情、研究、知识、数据和界面分别由 [`market-design/market_design.md`](market-design/market_design.md)、[`research-design/research_design.md`](research-design/research_design.md)、[`knowledge-design/wiki.md`](knowledge-design/wiki.md)、[`data-design/data_design.md`](data-design/data_design.md) 和 [`ui-design/DESIGN.md`](ui-design/DESIGN.md) 拥有。跨页旅程冲突时以本文为准，模块内部行为冲突时以模块合同为准。
>
> `prototype/` 只验证人类确认后的本文，不得反向创造业务规则。

## 1. 产品背景

投资者看到一个行业或股票时，最自然的问题是：现在的价格高估还是低估，是否值得继续关注，为什么？回答它不能只看 PE、ROE 或一份财报，也不能依赖用户每次重新教 Agent 应该关注什么。

真实分析需要把多类信息连成因果链：

1. 从行情广度和行业趋势中发现潜在方向；
2. 理解公司的业务结构和所属行业机制；
3. 拆分收入、价格、产能、成本、费用、利润和现金流；
4. 找到真正领先利润变化的商品价格、价差、供需、库存、订单或行业指标；
5. 使用适合该行业的财务与估值模型形成价值区间；
6. 将当前市场价格与价值区间比较，判断估值位置、安全边际和吸引力；
7. 持续用价格、财务、行业数据和事件验证这些假设。

现有工具往往只完成其中一段：行情软件给数据，通用 Agent 解读用户交给它的单份材料，知识工具负责保存内容，却没有主动提供行业方法、利润模型和估值框架。结果是用户仍需自己决定该看什么、怎样计算，以及新数据究竟改变了什么。

Vibe-Finance 的核心价值，是主动聚合行情、财务和行业数据，应用内置分析框架与 Skills，把数据转换成关于利润趋势、价值区间和当前估值的可解释判断。Wiki 负责让框架、事实和历史判断能够持续积累；报告负责呈现阶段结果；FCISU、来源位置、数据时间和时效负责保证判断可信。它们都是实现核心判断的手段，不是产品目的。

## 2. 核心用户与用户目标

### 2.1 核心用户

首版服务所有 A 股投资者。用户不需要预先已有关注方向：尚无方向时，通过行情广度和可视化看见市场结构、相对位置与变化，形成值得继续研究的行业或个股候选；已有关注股票时，直接纳入系统。两种起点进入同一研究流程。

### 2.2 核心目标

用户在任何时点都应能回答：

- 如果我还没有明确方向，当前哪些行业或个股值得进一步分析，依据是什么？
- 这家公司怎样赚钱，收入、成本、利润和现金流由什么驱动？
- 这个行业应使用什么分析方法，哪些数据是关键先行指标？
- 关键价格、价差、供需、库存、订单或财务指标正在向哪个方向变化？
- 当前价值区间如何计算，使用了哪些事实、假设和估值方法？
- 当前市场价格相对价值区间是偏高、合理还是偏低，安全边际和估值吸引力如何？
- 最近的价格、财务、行业趋势和事件是否改变了利润假设、价值区间或研究状态？
- 哪些证据支持判断，数据截至何时，什么条件会使判断失效？

## 3. 首版范围与边界

### 3.1 包含

- A 股行情广度探索、个股和行业详情；
- 手动或批量加入关注，并为个股选择“关注 / 跟踪 / 持有”标签；
- 行情、财务、估值、公告、研报和行业关键指标的聚合入口；
- 个股与行业两类分析对象及双向关系；
- 默认分析框架、通用方法、对象 Wiki 上下文和利润 / 估值模型的组合；
- 业务结构、收入成本、利润现金流、关键先行指标和行业趋势分析；
- 当前价格、价值区间、安全边际、估值吸引力和四态研究状态；
- 每周轻复核与事件驱动的深复核；
- 当前报告、页面上下文助手、结构化确认和持续更新；
- 作为支撑层的用户资料摄取、Evidence、Wiki、Memory、日志与本地恢复。

### 3.2 不包含

- 量化策略、回测、自动交易、自动下单或 tick 数据持久化；
- 明确买卖、点位或仓位指令；
- 全局研究项目、专题池、报告中心或正式报告基线；
- 报告版本列表、聊天历史列表、新建的通知中心或外部消息推送接口；
- 港美股与 A 股同等深度的完整研究闭环；
- 单独的公司实体和证券—公司映射；
- 因“持有”标签扩展出的成本、数量、仓位核算或组合管理。

港美股可以作为外围行情、产业链或可比信息进入分析，但不扩大首版承诺。

## 4. 信息架构与页面职责

| 页面 | 用户任务 | 不负责 | 详细合同 |
|---|---|---|---|
| 行情总览 | 广度发现、搜索、批量关注 | 持久研究结论 | `market-design/` |
| 行情－资讯 | 查看关注股票的消息聚合 | 新建外部推送渠道 | `market-design/` |
| 板块 / 行业详情 | 理解行业数据并加入研究 | 页面内自动生成长期结论 | `market-design/` |
| 个股详情 | 查看实时对象数据并加入研究 | 充当研究报告页 | `market-design/` |
| 研究－行业 | 管理关注行业、查看更新和进入对象 | 全局报告列表 | `research-design/` |
| 研究－个股 | 管理关注股票、标签、更新和对象入口 | 分裂成多个股票池 | `research-design/` |
| 研究对象页 | 分析利润、估值与关键变量并持续验证 | 暴露后台 Wiki 文件结构 | `research-design/` |
| 数据－数据源 | 管理外部信息通道与主动摄取节奏 | 把支撑项目当成数据源名称 | `data-design/` |
| 数据－研究资料 | 管理用户历史上传 | 展示个股 / 行业 Wiki | `data-design/` |
| 数据－配置 | 管理高级规则和恢复 | 要求普通用户理解知识编译或 Git |  `data-design/` |

跨页面的三条硬边界：

1. 个股和行业详情是无自动生成结论的数据 Dashboard；结论只在用户明确请求基本面速览，或对象已加入研究后出现。
2. 公共助手存在于所有页面，并可基于当前页面数据回答问题。
3. 研究结论只有一份，归属于具体对象；任何页面都不提供第二套结论或第二套通知。

## 5. 四条用户主线

四条主线对应用户每天实际做的四件事，也是首版业务验收的四组标准。它们共用同一批对象和同一份结论，不构成四个产品。

### 5.1 第一件事：从全市场发现值得研究的行业和股票

**目标：** 用户没有明确方向时也能形成候选，并判断哪些值得进入完整分析。

```text
查看指数 / 热力 / 行业趋势 / 估值 / 资金
→ 下钻行业或个股数据详情
→ 识别可能低估、趋势改善或关键指标变化的候选
→ 打开基本面速览确认候选
→ 手动或批量加入关注，个股同时选择关注 / 跟踪 / 持有
→ 系统装载默认或行业分析框架并建立初始分析
→ 用户查看当前价格相对价值区间的位置及其依据
```

已有标的的用户跳过前三步，直接搜索或批量输入股票，从基本面速览开始，汇入同一条流程。

用户反馈必须包括：加入成功、所选关注标签、占位已出现、初始化是否仍在进行，以及完成后可进入的明确入口。批量加入不要求用户逐个等待。

基本面速览的内容与呈现合同见 `market-design/`。初始分析允许信息稀疏，但不能只生成资料目录或通用财报摘要；最低交付是适用分析框架、业务和利润驱动、关键先行指标、可用的初始估值方法、少量有证据事实、明确知识缺口，以及当前价格与初始价值区间的关系。

**验收：**

- 能从行情定位行业或个股，单个和批量都能加入；
- 加入后立即出现关注卡，初始化不阻断用户继续浏览；
- 加入前就能拿到基本面速览，并据此判断是否值得深入；
- 可直接加入股票并选择关注 / 跟踪 / 持有；三种标签共用同一研究流程和列表，可随时修改；
- 自动建立主行业和双向关系；
- 能演示初始化中、完成、三次失败后恢复。

### 5.2 第二件事：你关注的，现在怎么样了

**目标：** 用户在任何时点都能知道关注对象的当前状态和最近变化。

```text
打开研究页
→ 先看最近更新：待复核、状态变化、报告更新、复核后结论不变
→ 扫一遍对象卡：关注标签、研究状态、关键变化时间、未查看标记
→ 点进对象页：为什么是这个状态、依据是什么、数据是哪天的、什么会改变判断
```

**验收：**

- 行业 / 个股两个 Tab 能容纳占位、完成、待复核和恢复对象；
- 对象页按统一骨架阅读，个股与主行业可双向跳转；
- 状态可解释且不随 tick 闪烁；
- 报告、研究依据和关系按已确认骨架呈现并可下钻。

### 5.3 第三件事：新消息自动整理好、分析清楚

**目标：** 新资料不论来自系统还是用户，都自动归到对应对象并保持可追溯，用户不需要自己整理文件夹。

```text
新资料进入：系统按节奏主动获取，或用户上传文件、URL、粘贴文本
→ 识别所属对象，歧义时请用户选择
→ 登记为原始资料，只追加不改写
→ 提取证据并维护对象知识，冲突并存并标记存疑
→ 影响关键变量时标记待复核
```

用户纠错和删除不做无痕修改：编辑或删除前展示受影响的对象、证据和当前报告，二次确认后，资料修改、证据重算、知识更新、报告待更新、日志和 checkpoint 构成一次原子事务。

系统主动获取的节奏由 `data-design/` 拥有，资料到位后是否复核由 `research-design/` 拥有。

**验收：**

- 文件、URL 和文本可导入并查看，批量导入能处理对象识别歧义；
- 编辑或删除前展示影响并二次确认；
- 完成后更新证据、知识、报告状态、日志和 checkpoint；
- 事务失败不留下资料与知识不一致的半成品；
- 用户可查看变更并通过新动作恢复；
- 界面不暴露 Git 和 Wiki 技术细节。

### 5.4 第四件事：给你可靠的结论，有重要动态才更新

**目标：** 维持“市场价格—利润假设—价值区间”的关系，并且只在真有动态时才改口。

```text
实时价格更新
→ 基于最近完成的价值区间更新估值位置和安全边际，不改结论

每周轻复核
→ 检查指标、阈值和未处理资料
→ 输出「查过了，没变」或标记待复核

定期报告到位、重大事件或用户要求
→ 深复核：重算利润假设、估值模型和价值区间
→ 更新研究状态、当前报告和最近更新
→ 用户查看变化原因、证据和失效条件
```

价格变化本身改变估值位置和安全边际，但不重写业务判断或价值区间。定期报告以实际摄取到为准，不按日历季度；逾期未到位时系统标记证据过时并说明缺哪一期，不用旧输入空转一遍。复核结果同时进入对象“最近更新”和现有关注股票消息聚合，不新建外部推送接口。

用户想试别的假设时，助手识别意图并调用结构化估值输入，用户确认后由确定性函数重算；临时情景不改变当前报告，采用为持续假设需要再次确认。

**验收：**

- 四态研究状态均有可展开原因和证据；
- 当前价格变化能基于最近价值区间更新估值位置和安全边际；
- 轻复核按周发生并能表达“查过了，没变”，且不重写报告；
- 深复核由报告到位或重大事件触发，逾期缺报时如实标记而非伪装已复核；
- 复核结果能区分“改变”和“不变”，并进入已有消息聚合；
- 估值情景由 Agent 调用结构化输入、用户确认、确定性函数重算，采用持续假设需再次确认；
- 任意页面助手知道当前页面和筛选，页面切换或刷新后没有历史会话；
- 输出不包含明确买卖、点位或仓位指令。

## 6. 加入、初始化与关注生命周期

### 6.1 加入反馈

- “加入研究”是异步动作，但对象立即进入“关注股票”或“关注行业”。
- 加入个股时可选“关注 / 跟踪 / 持有”，默认“关注”；这是同一列表中的轻量标签，可以随后修改，不创建不同股票池、不改变初始化和研究 Pipeline。
- 对象卡不持续暴露队列、步骤或 Agent 内部状态。
- 用户点击未完成对象时，系统读取事件状态：已完成则进入对象页；未完成则提示“正在建立研究”；暂停失败则提供恢复。

### 6.2 自动行业初始化

加入个股后，系统识别主行业：

- 已有行业对象时建立关系并补充证据；
- 不存在时创建行业占位并按相同规则初始化；
- 个股和行业均能跳转到对方；
- 关系必须记录证据和截至时间。

### 6.3 失败与恢复

- 初始化失败自动重试三次；
- 三次后暂停，不循环制造噪声；
- 用户再次点击对象即可恢复；
- 已形成的成功资产不能被失败结果覆盖。

### 6.4 取消与删除

- 取消关注只停止主动更新并移出列表；
- 研究知识继续保留，可再次关注后恢复；
- 删除用户资料必须在“研究资料”中单独执行并先展示影响；
- 彻底删除从研究对象页“更多 → 删除研究档案”进入，移除该对象的研究状态、当前报告、研究依据、Memory、关系和关注状态；
- 删除确认必须明确告诉用户“你上传的原始资料不会删除”，这些资料保留在“研究资料”中并解除对象关联；
- 删除完成后可从“数据 → 配置 → 变更记录”恢复。界面只使用研究档案、原始资料和恢复等业务语言，不暴露 Wiki、Git 或 commit。

## 7. 研究对象页与分析方法的跨页约定

每个个股或行业对象沿用同一阅读顺序，不根据用户经验改变页面结构：

```text
研究状态 → 实时指标 → 当前报告 → 研究依据 → 关系跳转 → 助手
```

分析默认主线同样对所有对象一致：

```text
业务 / 行业机制 → 收入、成本与利润拆分 → 财务模型 → 关键先行指标
→ 用实时数据替换滞后信息 → 利润趋势与现金流 → 适用估值模型与价值区间
→ 当前价格、估值位置与安全边际 → 证伪条件
```

三条跨页边界：

- 每个对象只有一份当前报告，不提供版本列表；
- 产品可以表达偏高、合理、偏低或证据不足及其原因，但不输出买卖、点位或仓位指令；
- 不同行业使用不同估值方法，不把所有行业压成统一评分。

状态定义、指标要求、报告结构、方法组合、Skills 装载和估值情景的完整合同见 `research-design/`；通用方法与 Agent 动态发现规则见 `research-design/analysis_frameworks.md`。

## 8. 支撑层与资料流转

支撑层保证核心判断连续、可信、可恢复，本身不是用户目标。跨页需要成立的是：

- 每个对象都有一份结构就绪、内容允许稀疏的研究档案，公司自动关联所属行业，双向可查；
- 原始资料只追加不改写，出处、发布时间、数据截至时间和获取时间一直保留；
- 关键陈述标注 FCISU、来源位置、数据时间和时效状态，并能回到原文；
- 事实冲突并存并标记存疑，不静默覆盖；
- 用户假设在获得外部证据前不晋升为事实；
- 长期有价值的假设、修正和待验证问题进入对象 Memory，完整聊天不进入；
- 所有确认后的知识修改形成一条变更记录和一个本地 checkpoint，用户看到的是“变更记录”和“恢复”，不是 hash、分支或 Wiki 版本。

对象知识目录、Schema 演化规则、证据合同、Memory 和 Git 生命周期的完整定义见 `knowledge-design/wiki.md`；资料 CRUD、数据通道和配置界面见 `data-design/`。

## 9. 助手与结构化动作

公共助手跨越所有页面，因此其会话语义和动作边界由本文统一约定；研究页面的上下文细节由 `research-design/` 承担。

### 9.1 会话语义

- 助手存在于所有页面；
- 页面切换或刷新后开始空白对话；
- 不维护聊天历史列表或全局 Session；
- 同一路由筛选变化不主动清空对话，但必须刷新页面上下文；
- 长期上下文来自确定性的 Wiki、Memory、Skills 和页面数据，而不是历史聊天。

### 9.2 上下文装载

| 页面 | 确定性上下文 |
|---|---|
| 个股研究 | 个股 Wiki、对象 Memory、关联行业 Wiki、启用 Skills、页面快照 |
| 行业研究 | 行业 Wiki、对象 Memory、通用 Skills、页面快照 |
| 行情 / 数据 | 页面类型、筛选条件、可见数据和时间戳 |

大体量和最新数据由工具按需获取。助手回答先给判断，再给依据、缺口和改变判断的条件。

### 9.3 结构化 UI Tools

Agent 负责识别意图和提出动作；前端负责确定性输入与确认；领域命令负责执行。

| 动作类型 | 行为 |
|---|---|
| 查询、取数、临时计算 | 可直接调用工具 |
| 修改、删除、采用持续假设 | Tool 返回结构化表单和影响摘要，用户确认后执行 |
| 已启用的后台更新 | 自动执行、写日志和 commit，不逐次打扰 |

Agent 不直接模拟点击，也不绕过确认修改持久状态。执行结果返回当前页面会话，由助手解释成功、失败和下一步。

## 10. 跨页降级原则

失败的完整语义由各模块合同拥有。跨页面必须一致成立的是四条：

1. **局部失败局部降级。** 单个数据块、Dashboard 或工具失败只影响自身，显示失败原因、最后成功时间和过期状态，其余页面继续可用。
2. **不用空结果覆盖成功结果。** 知识、报告和研究状态的更新失败时保留最后一次成功内容并提供重试。
3. **证据不足要说出来。** 说不清就用灰色状态并列出缺口，不用红黄绿伪装确定性，也不把工具故障映射成研究结论。
4. **确认后的修改必须原子。** 不能完整落盘、写日志并形成 checkpoint 的，视为整体失败并保留原状态。
