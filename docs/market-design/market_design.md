# 行情模块合同

> 本文拥有行情总览、资讯、行业详情、个股详情四类页面的用户职责，「加入研究」入口，以及基本面速览的产品合同。跨页面旅程以 [`../flow_design.md`](../flow_design.md) 为准；总览的 Dashboard 信息架构以 [`market_overview_standard.md`](market_overview_standard.md) 为准；加入之后的研究行为以 [`../research-design/research_design.md`](../research-design/research_design.md) 为准；证据与知识结构以 [`../knowledge-design/wiki.md`](../knowledge-design/wiki.md) 为准。

## 1. Responsibility

行情模块回答用户进入产品后的第一个问题：现在市场里有什么、这个行业或这家公司是什么情况、值不值得我花时间研究它。它是发现环节，不是研究环节。

本模块负责：

- 行情总览的广度发现、搜索和批量关注；
- 关注股票的公告与新闻聚合；
- 行业详情与个股详情的实时数据呈现；
- 「加入研究」入口，包括单个加入、批量加入和关注标签选择；
- 基本面速览：帮助用户在加入前判断是否值得深入的第一层结论。

本模块不负责：

- 持久研究结论、研究状态、当前报告和价值区间；
- 关注列表的管理、更新提示和对象页骨架；
- 用户资料 CRUD、数据源配置和 Schema；
- 生成买卖、点位或仓位指令。

## 2. Information architecture

行情一级导航固定为三页：

```text
总览 | 资讯 | 板块
```

行业详情与个股详情是从总览、板块、搜索或资讯下钻进入的对象页面，不占用一级导航。

| 页面 | 用户任务 | 主要内容 | 不负责 |
|---|---|---|---|
| 总览 | 广度发现、搜索、批量关注 | 指数、估值、热力、情绪、成交、资金、搜索结果 | 持久研究结论 |
| 资讯 | 查看关注股票的消息聚合 | 公告、新闻、研究变化，以及按需打开的助手分析 | 新建外部推送渠道 |
| 板块 / 行业详情 | 理解行业数据并加入研究 | 行业表现、产业结构、景气数据、重点公司 | 页面内自动生成长期结论 |
| 个股详情 | 查看实时对象数据并加入研究 | 行情、财务、估值、公告、研报、资金等 | 充当研究报告页 |

## 3. 总览

总览遵循 [`market_overview_standard.md`](market_overview_standard.md) 的 Dashboard 契约、分组顺序、刷新语义和文案纪律。本文只补充两条跨页职责：

- 搜索是页面级能力，结果可直接选择一个或多个对象加入研究；
- 「实时行情」开关只控制总览 Dashboard 的自动刷新，不影响详情页和研究页。

## 4. 资讯

资讯聚合当前关注股票的公告与新闻，并接收研究模块产生的研究变化条目。

- 消息按对象归集，可跳转到对应的详情页或研究对象页；
- 研究状态变化、报告更新和「复核后结论不变」复用本页聚合能力，不新建通知中心；
- 首版不提供外部推送接口和第三方消息渠道；
- 助手可以按需分析当前可见的消息，但本页不生成持久结论。

## 5. 行业详情

行业详情是无自动生成结论的数据 Dashboard，至少表达：

- 行业身份：分类、稳定标识、定位描述、数据更新时间；
- 行情指标：与个股详情保持同一密度和数字排版；
- 产业链结构：分环节可选中，选中后更新当前环节的说明与数据；
- 景气数据：每项独立呈现数值、变化、统计区间和来源，不合成综合评分；
- 重点公司：可切换市场、估值、盈利、规模等维度，不改变表格布局。

行业详情不输出推荐、目标价或买卖结论。每个数据块标明口径与数据日期；单块失败不阻断其余内容。

## 6. 个股详情

个股详情同样是无自动生成结论的数据 Dashboard，至少表达当前价格与日 K、财务、估值、公告、研报和资金数据，并提供资料入口与所属行业跳转。

个股详情不承担研究对象页职责：没有研究状态灯、没有当前报告、没有价值区间。用户加入研究后，这些内容出现在研究对象页。

## 7. 基本面速览

### 7.1 用户价值

速览回答一个具体问题：这家公司值不值得我花时间深入研究。它是完整分析的第一层输出，不替代估值与价值区间判断。

用户不需要先准备财报、先指定分析方法、先说明应关注什么。系统主动形成速览。

### 7.2 触发与位置

速览是详情页上按需打开的一层，不是详情页数据体的一部分。用户在个股或行业详情页明确请求时生成；对象加入研究后，速览在研究对象页持续可用并随分析更新。

这样详情页保持「无自动生成结论的数据 Dashboard」的定位：页面默认只呈现接口数据，结论只在用户明确要求时产生。

### 7.3 内容合同

速览至少表达：

1. 这家公司靠什么赚钱：主营业务与所属行业；
2. 各业务对收入和归母利润的贡献占比；
3. 利润由什么驱动；
4. 当前应重点观察哪些变量与先行指标；
5. 主要风险；
6. 知识缺口：还没搞清楚什么；
7. 每项数据的口径、来源和数据时间。

行业对象的速览把前三项替换为行业机制、产业链位置和景气驱动，其余一致。

### 7.4 呈现纪律

速览以结构化 Dashboard 呈现，不输出长文本段落：

- 各业务收入与利润占比用可视化和紧凑表格；
- 关键观察点与风险用结构化卡片；
- 知识缺口独立成块，不混在结论里；
- 先给结论与占比，再给依据、来源与缺口。

每个数字可以查到出处和数据日期。证据不足时明说缺什么，不用通用财报摘要填满结构。

### 7.5 边界

- 速览不给出价值区间、估值位置、安全边际和研究状态；
- 速览不改变研究对象页的既定信息架构；
- 速览生成失败时保留详情页的接口数据，说明失败原因并允许重试。

## 8. 加入研究

### 8.1 入口

总览搜索结果、板块、行业详情页和个股详情页均提供「加入研究」。用户可以加入一个，也可以从发现结果中批量加入。

加入个股时可选「关注 / 跟踪 / 持有」标签，默认「关注」，之后可修改。标签不产生不同的研究流程或独立股票池。

### 8.2 反馈

加入是异步动作，但用户反馈必须立即包含：

- 加入成功，以及加入个股时所选的关注标签；
- 对象已出现在「关注股票」或「关注行业」中；
- 初始化是否仍在进行；
- 完成后可进入的明确入口。

批量加入不要求用户逐个等待，也不逐个弹窗确认。批量结果需要区分已加入、已在列表中和加入失败三类，并允许对失败项单独重试。

### 8.3 交接边界

行情模块的责任在「对象已加入并给出反馈」处结束。占位卡、初始化重试、主行业关系建立和后续研究由研究模块与知识模块承担。

## 9. Public interfaces

行情模块至少产生：

- 用户请求加入对象（单个 / 批量，含关注标签）；
- 用户请求生成基本面速览；
- 用户从详情页跳转到已有研究对象。

行情模块至少消费：

- 对象是否已在关注列表中；
- 对象初始化状态，用于决定「加入研究」按钮显示为可加入还是「已加入 · 去研究」；
- 数据通道的连接与降级状态。

## 10. Failure semantics

| Failure | User-visible behavior | Preserved state |
|---|---|---|
| 单个 Dashboard 数据失败 | 该块显示失败、最后成功时间和过期状态 | 其余 Dashboard 继续可用 |
| 详情页某个数据块失败 | 该块单独降级，标明数据时间 | 页面其余内容和加入入口可用 |
| 基本面速览生成失败 | 说明失败原因并可重试 | 详情页接口数据不受影响 |
| 速览证据不足 | 明确列出缺口 | 不用通用摘要伪装完整 |
| 批量加入部分失败 | 区分成功、已存在和失败，失败项可单独重试 | 已成功加入的对象 |
| 对象识别歧义 | 展示候选并等待用户选择 | 用户当前输入 |

## 11. Business validation

首版验收必须证明：

- 用户在没有明确方向时，能从总览的广度数据形成候选并下钻到行业或个股；
- 行业详情与个股详情不出现推荐、目标价、综合评分或买卖结论；
- 用户在加入研究之前就能拿到基本面速览，并据此判断是否值得深入；
- 速览以占比可视化和结构化卡片呈现，不是长文本段落，且每个数字可查出处和数据日期；
- 加入单个和批量加入都能立即得到反馈，不要求用户等待初始化；
- 加入个股时可选择关注标签，默认「关注」；
- 详情页能与对应的研究对象页双向跳转，且不重复承担研究对象页职责；
- 单个数据块或速览失败不会导致整页不可用。
