# 行情总览标准

> **定位：** 行情总览是 Vibe-Finance 的 Dashboard 页面标准。它规定信息如何分层、一个 Dashboard 如何构成、数据如何决定内容形态；不是某一页的静态样式说明。  
> **适用范围：** 行情总览，以及后续所有由多个市场数据模块构成的页面。视觉 token 和 CSS 真源仍以 [`../ui-design/DESIGN.md`](../ui-design/DESIGN.md) 与 `prototype/shared.css` 为准；行情模块的页面职责以 [`market_design.md`](market_design.md) 为准。

## 1. 核心原则

**页面不是卡片的堆叠，而是按投资决策顺序组织的一组独立 Dashboard。**

- 行情广度和可视化必须帮助尚无明确方向的用户看见市场结构、相对位置和变化，形成可继续研究的行业或个股候选，而不只服务已有自选监控。
- 导航负责定位，不重复展示数据。
- 分组负责阅读顺序，不承担 Dashboard 的数据和交互责任。
- Dashboard 是唯一可复用的数据单元：拥有标题、内容、刷新与更新时间。
- 内容的视觉形态由数据类型决定，不为了统一而强行套同一种卡片。

## 2. 信息架构

| 层级 | 职责 | 标准 |
|---|---|---|
| 一级导航 | 切换市场域 | 总览 / 板块 / 资讯；不复制主区数据。 |
| 页内目录 | 定位同页分组 | 每项为标题 + 一句短描述；点击仅滚动定位，并随主区滚动同步。 |
| 页面级控件 | 跨 Dashboard 操作 | 检索固定在主区顶部，不作为目录项。 |
| 分组 | 表达阅读顺序 | 指数 / 情绪 / 资金；不再生成一套标题栏或刷新状态。 |
| Dashboard | 呈现一类独立数据 | 独立标题栏、数据体、刷新动作和更新时间。 |

总览的固定分组关系：

- **指数：** 大盘指数、指数市盈率。
- **情绪：** 市场热力图、市场情绪、短线情绪。
- **资金：** 全市场成交额 TOP20、资金轮动。

## 3. Dashboard 契约

每个 Dashboard 都使用同一外部契约：

```text
图标 + 标题 + 一句短说明 ｜ 刷新 + 更新时间
内容体
```

| 字段 | 要求 |
|---|---|
| `id` | 稳定且唯一，用于目录定位、刷新和状态管理。 |
| `icon` | 统一使用同尺寸线性图标；当前规则是所有 Dashboard 都有图标。 |
| `title` | 数据对象名称，使用名词短语。 |
| `summary` | 只说明数据范围或统计口径，保持一句。 |
| `refreshedAt` | 该 Dashboard 自己的更新时间，不共享或伪造全页时间。 |
| `onRefresh` | 只刷新该 Dashboard 的数据与时间，不重置页面、其他组件或检索状态。 |
| `body` | 由数据类型决定的内容体；不重复标题、刷新和时间。 |

概念上可视为：

```ts
type DashboardSpec = {
  id: string;
  icon: Icon;
  title: string;
  summary: string;
  refreshedAt: Date;
  onRefresh: () => Promise<void>;
  body: Renderable;
};
```

### 组件边界

- **大盘指数**与**指数市盈率**是相邻但独立的 Dashboard。
- **市场热力图**整体是一个 Dashboard；行业热力图、个股热力图是它的内部内容，不各自拥有彩色栏头、刷新或时间。
- 市场情绪、短线情绪、成交额 TOP20、资金轮动均为独立 Dashboard。
- 分组容器只能排布和锚定 Dashboard，不能吞并其标题栏，也不能加一套重复控制。

## 4. 内容与视觉的对应关系

| 数据类型 | 首选内容形态 | 目的 |
|---|---|---|
| 主要指数报价 | 指标卡片组 | 快速比较数值和涨跌。 |
| 指数估值位置 | 横向比较条 | 比较数值与历史分位。 |
| 行业 / 个股涨跌分布 | 热力图 | 面积表达权重，颜色表达涨跌。 |
| 市场广度与状态 | 状态块 + 指标格 | 判断市场温度和扩散度。 |
| 短线表现 | 统计格 + 排名表 | 判断连板、封板等短线状态。 |
| 成交额排名 | 排名表 | 直接比较活跃标的。 |
| 资金轮动 | 双栏流向列表 | 对照流入与流出方向。 |

大盘指数使用固定的 **3 / 4 / 3** 语义排布：首排 3 个 A 股核心指数、次排 4 个 A 股宽基、末排 3 个港股指数。响应式布局可以随屏幕收缩，但不能丢失这层市场分组语义。

不为装饰加入 K 线缩略图、重复大卡片、AI 解释块或与判断无关的可视化。

## 5. 视觉与文案纪律

### 5.1 一个组件，一层标题

- 标题栏位于页面平面；内容体形成一个完整、克制的表面。
- 一个 Dashboard 内不再出现第二条同级标题栏。
- 避免卡片套卡片、局部彩色栏头和无业务含义的阴影层级。
- 热力图内部的行业与个股面板通过布局区分，而不是通过两条子标题栏区分。

### 5.2 少文案，强定位

- 页面级说明只交代用途，例如“指数 / 情绪 / 资金一屏定位”。
- 目录项与 Dashboard 说明各限一句，补充范围或口径，不复述标题。
- 标题优先用名词，不使用营销语或完整解释句。
- 默认不放问号提示图标；确有无法在一句话内说明的口径时，才提供按需展开的详情。

### 5.3 图标与语义色

- 图标策略必须全局一致：当前为全部 Dashboard 使用 15px 线性图标。
- 图标用于快速识别数据类型，不用于装饰。
- 涨跌红绿仅表达市场语义；不可借用为品牌色或普通功能状态。

## 6. 交互与状态

- 左侧“指数 / 情绪 / 资金”与主区分组双向同步：点击滚动，滚动更新选中态。
- 刷新按钮属于单个 Dashboard；刷新反馈和时间只在该组件内变化。
- 行情总览顶栏提供“实时行情”开关：默认开启、控制总览 Dashboard 的自动刷新；关闭后停止自动刷新但不禁用单个 Dashboard 的手动刷新。它不替代组件自身的更新时间。
- 检索是页面级能力：不应因刷新、切换目录或重新进入页面而无意携带旧查询。
- 当数据暂缺时，Dashboard 应保持其标题、刷新和时间位置，用明确空态替换内容体，不能让结构坍塌。

## 7. 验收清单

一页满足以下条件，才算遵循行情总览标准：

- [ ] 导航、页内目录、分组和 Dashboard 的职责没有重叠。
- [ ] 每个 Dashboard 都有统一标题栏与独立刷新/时间。
- [ ] 没有 Dashboard 在内容体内重复标题、刷新或更新时间。
- [ ] 图标策略全局一致，标题与说明保持短小。
- [ ] 热力图作为一个 Dashboard，内部子图不额外出现彩色栏头。
- [ ] 数据展示形态与数据类型匹配，而非统一套卡。
- [ ] 点击目录只定位；刷新单个组件不影响其他组件和检索。
- [ ] 新增模块可只提供一个 `DashboardSpec` 和内容体即可接入页面。

## 8. 反例

- 用左侧目录再次罗列主区的数据卡或统计数字。
- 把“指数 / 情绪 / 资金”做成有刷新和时间的伪 Dashboard。
- 把热力图拆成两个带独立彩色标题栏的组件。
- 一部分标题有图标、一部分没有；或混用不同大小、不同风格图标。
- 在 Dashboard 标题旁堆叠问号、长段说明、来源提示和操作按钮。
- 每一层都加圆角、描边和阴影，导致内容层级多于业务层级。
