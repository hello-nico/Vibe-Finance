# 首版通用分析框架与方法参考

> 本文拥有 Vibe-Finance 首版通用分析方法、Agent 动态发现规则和案例参考。用户流程以 [`../flow_design.md`](../flow_design.md) 为准，运行合同以 [`research_design.md`](research_design.md) 为准，Wiki 结构以 [`../knowledge-design/wiki.md`](../knowledge-design/wiki.md) 为准。
>
> 本文参考用户既有 Second Brain 中经过实际使用的内容。Second Brain 是只读参考；公司和行业案例用于说明通用方法如何落地，不是预置行业模板、固定 Schema 或运行时依赖。

## 1. 目的

“开箱即用”指 Agent 能在用户未指定具体方法时，使用少量通用分析方法阅读公司和行业资料，发现真正影响利润与估值的变量，继续寻找缺失证据，并把稳定认识维护进对象 Wiki。

它不意味着上线前为每个行业准备完整 Skill、利润公式或必填字段。行业知识应在真实分析中逐步形成，经过反复验证后才考虑沉淀为可复用方法。

## 2. 方法与 Wiki 的分工

| 层 | 负责什么 | 不负责什么 |
|---|---|---|
| 通用分析方法 | 教 Agent 怎样思考、提出问题、识别变量、继续找证据 | 预先给出每个行业的答案 |
| `purpose.md` | 固定对象分析目的、核心问题和边界 | 保存不断变化的事实 |
| `schema.md` | 维护 Wiki 组织约定、页面类型、分析框架和工作规则 | 枚举所有行业的固定字段 |
| Raw | 保存原始资料和数据引用，只追加不改 | 承担整理和判断 |
| Wiki | 按 Schema 维护已经形成的对象知识、关系、冲突与概览 | 充当实时行情数据库 |
| Memory | 保存对后续分析有价值的对话增量、用户假设和待验证问题 | 保存完整聊天历史 |
| 模型与当前报告 | 使用 Wiki、动态数据和假设形成当前利润与估值判断 | 反过来替代来源和长期知识 |

## 3. 默认分析主线

```text
理解对象与当前问题
→ 读取 purpose、schema、wiki 和相关 Raw
→ 理解业务 / 行业机制
→ 拆分收入、成本、利润与现金流
→ 识别关键变量、噪音和证据缺口
→ 主动补充公司、行业与市场数据
→ 判断利润趋势和先行信号
→ 选择适用估值方法
→ 比较当前价格、价值区间与安全边际
→ 给出依据、假设、反证和失效条件
→ 将稳定增量维护回 Wiki，记录 Log
```

### 3.1 顺序纪律

- 没有理解公司怎样赚钱，不急于套估值倍数；
- 没有识别主要收入和成本变量，不把财报摘要当作分析；
- 没有验证现金流，不把会计利润直接当作股东可得价值；
- 没有理解行业和资产特征，不机械使用 PE 或 DCF；
- 没有来源、时间和口径，不输出高确定性结论；
- 发现新分析维度后按需更新 Schema 或 Wiki，不预先制造空结构。

## 4. Agent 动态发现过程

Agent 不需要先命中“电解铝 Skill”“火电 Skill”等行业模板。给定公司后：

```text
读取证券身份、主营和已有 Wiki
→ 用通用方法提出第一轮问题
→ 从财报、公告和行业资料识别候选利润变量
→ 检索并验证候选变量的影响路径和量级
→ 区分事实、来源主张、推断和综合判断
→ 形成当前最小可用分析
→ 将已验证且以后会复用的内容写入 Wiki
```

例如，Agent 分析一家电解铝公司时，不预先假定必须提取氧化铝耗用量。它先从主营和成本披露发现电解铝是利润主体、氧化铝是主要成本，再继续寻找耗用系数、采购口径、电价和权益产能。这里“量 × 价 − 成本”来自通用方法；氧化铝是否关键以及具体数值来自本次证据。

若证据只支持方向而不能量化，保留为 Inference 或 Gap，不为了填满框架而制造数字。

## 5. 通用分析方法

### 5.1 业务与行业机制

至少追问：

- 公司卖什么，客户是谁，收入怎样形成；
- 哪些业务贡献收入，哪些业务真正贡献利润和现金；
- 量、价、成本、产能、利用率和市场份额分别如何变化；
- 定价权、成本优势和竞争壁垒来自哪里；
- 行业供需、政策和竞争如何传导到公司；
- 当前市场可能在为哪部分利润或预期定价。

这些是提问方向，不是固定 Wiki 字段。Agent 根据对象和证据决定页面结构。

### 5.2 利润拆分

通用利润桥只提供起点：

```text
收入 ≈ 数量 × 实现价格 + 其他收入
毛利 = 收入 − 变动成本 − 必要固定成本
经营利润 = 毛利 − 折旧摊销 − 期间费用 ± 经营性其他项
归母净利润 = 税后利润 − 少数股东损益 ± 非经常性项目
Owner Earnings ≈ 经营现金流 − 维护性资本开支
```

Agent 需要根据真实业务改写公式，并判断：

- 哪些变量一动就显著改变利润；
- 哪些变量只影响长期竞争力或估值；
- 哪些只是会计、季节或短期噪音；
- 哪些关系已有历史数据锚定；
- 哪些只是模型假设；
- 公司是否通过长协、套保、一体化或合同结构对冲了暴露。

### 5.3 财报阅读

财报主要用于量化和验证，不应成为唯一分析起点：

1. 先理解主营、行业和候选利润变量；
2. 在财报中寻找分部收入成本、量价、产能、股权、现金流和资本开支；
3. 验证候选变量是否真的影响公司利润；
4. 用更新数据替换已经滞后的关键输入；
5. 处理季节性、库存、结算周期、套保和一次性项目。

禁止未经季节性验证直接将单季度利润乘四，也不得混用物理产能、权益产能、产量、销量和加工品口径。

### 5.4 现金流验证

- 解释经营现金流与净利润差异；
- 分解应收、存货、预付、折旧、减值和营运资本；
- 区分维护性与成长性资本开支，无法可靠拆分时标记假设；
- 检查现金用于分红、偿债、扩产、并购还是回购；
- 对重资产、高杠杆、永续债和少数股东结构单独分析。

`OCF / NP` 只是线索，不能机械作为利润质量结论。

### 5.5 关键指标与先行信号

Agent 从利润变量反向寻找可持续观察的数据。候选指标需要检查：

- 是否存在可解释的利润传导关系；
- 影响量级是否足够重要；
- 是否早于财报或能验证财报趋势；
- 是否有稳定来源、时间和口径；
- 公司是否实际暴露于该变量；
- 关系是否可能因长协、套保、业务结构或政策改变而失效。

成熟后，Wiki 可以记录指标、对应变量、传导方向、更新频率、时滞、来源、阈值和失效条件；这些内容来自分析结果，不是全行业预置清单。

### 5.6 估值与资产定价

Agent 先回答“市场正在为什么定价”，再选择方法：

| 情况 | 可考虑的方法 |
|---|---|
| 稳定可分配现金流 | DDM、DCF、FCF 收益率、股息率比较 |
| 商品或利润周期明显 | 正常化利润、周期情景、NAV、适用倍数 |
| 多分部复合资产 | SOTP 与分部利润情景 |
| 高杠杆重资产 | 分部估值、现金流与债务覆盖、DCF / DDM |
| 高增长且利润未稳定 | 收入 / 利润情景、单位经济性和可比估值 |
| 证据不足 | 明确无法可靠估值，并列出缺口 |

估值结果至少表达：

- 方法及适用原因；
- 当前价格及数据时间；
- 事实输入与模型假设；
- 情景及关键敏感变量；
- 价值区间、估值位置与安全边际；
- 偏高、合理、偏低或证据不足的原因；
- 反证和失效条件。

确定性计算由工具完成，Agent 负责组织问题、选择方法、准备输入和解释结果。

### 5.7 跟踪与证伪

监控条件应从当前利润和估值判断反推，而不是预先配置所有指标：

- 哪个事实变化会改变利润公式；
- 哪个行业信号会改变趋势判断；
- 哪个价格变化只改变安全边际；
- 哪个假设失效会要求更换估值方法；
- 多长时间没有新证据后应将结论标记为趋旧。

## 6. 通用方法如何沉淀

默认不为每个行业创建 Skill。只有同时满足以下条件，才考虑将经验沉淀为通用方法：

1. 已在多个对象或多次分析中重复出现；
2. 方法描述的是稳定的思考过程，而不是某只股票的答案；
3. 不依赖大量易过时的固定字段；
4. 能明确适用边界和失败条件；
5. 沉淀后能减少重复工作，而不会提高维护成本。

沉淀形式可以是方法页、Prompt Template、Skill 或确定性工具。对象特有知识继续留在对象 Wiki，行业结构知识留在行业 Wiki。

## 8. 证据与时间底线

关键数字和判断必须包含：

- FCISU：Fact、Claim、Inference、Synthesis、Unattributed；
- 来源和可回放位置；
- 数据日期、报告期间或行情时点；
- 口径、单位和时效状态；
- 冲突、缺口和失效条件。

这些信息可以直接附着在 Wiki 的关键段落、表格和引用上，不要求把每句话拆成独立文件或数据库记录。

## 9. 实施验收边界

后续实现至少证明：

1. Agent 在没有行业专用 Skill 的情况下，可以从通用方法和对象资料开始分析；
2. Agent 能主动发现并验证对象特有的利润变量，而不是只复述财报；
3. 新形成的稳定认识能按对象 Schema 更新现有 Wiki 页面，而不是无限追加摘要；
4. 新问题暴露新的稳定分析维度时，可以有控制地演化 Schema；
5. Wiki、动态数据、模型假设和当前报告保持分层；
6. 关键输出满足 FCISU、来源、数据时间和失效条件；
7. 口径冲突、时点错配或证据不足会显式降级；
8. 输出不包含明确买卖、点位或仓位指令。
