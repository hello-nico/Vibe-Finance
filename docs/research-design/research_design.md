# 研究模块合同

> 本文拥有研究页、研究对象页、研究状态、复核节奏、当前报告、研究方法和页面助手的产品合同。跨页面旅程以 [`../flow_design.md`](../flow_design.md) 为准；证据和知识结构以 [`../knowledge-design/wiki.md`](../knowledge-design/wiki.md) 为准；加入研究之前的发现、详情页和基本面速览以 [`../market-design/market_design.md`](../market-design/market_design.md) 为准。

## 1. Responsibility

研究模块把聚合的行情、财务和行业数据转换成可解释分析，帮助用户回答公司怎样赚钱、利润由什么驱动、哪些指标领先、当前价格高估还是低估、为什么，以及什么变化会改变判断。

本模块负责：

- 关注行业和关注股票的列表、占位、关注标签与更新反馈；
- 个股 / 行业对象页的统一阅读骨架；
- 四态研究状态及待复核语义；
- 轻复核与深复核的节奏、触发条件和缺报兜底；
- 每个对象唯一的当前报告；
- 业务、收入成本、利润现金流、先行指标和行业趋势分析；
- 财务模型、估值模型、价值区间与当前价格比较；
- 默认主线、通用 Skills、对象 Wiki 上下文和用户方法的运行组合；
- 当前页面助手和 Agent 驱动的结构化研究动作。

本模块不负责：

- 行情广度发现或详情 Dashboard 的数据分组；
- 基本面速览的内容与呈现合同；研究对象页复用该合同，但它由行情模块拥有；
- 系统主动获取外部新资料的调度；
- 用户资料 CRUD、Schema 和 Skills 的配置界面；
- 全局报告中心、研究项目、专题池或聊天历史；
- 自动交易、量化回测、买卖点或仓位指令。

## 2. Information architecture

研究页只有两个二级 Tab：

```text
行业 | 个股
```

每个 Tab 均包含：

1. 最近更新；
2. 搜索和轻量标签筛选；
3. 关注对象列表；
4. 对象卡上的关注标签、研究状态、更新时间和待复核 / 未查看标记。

个股加入时可选一个内置关注标签：“关注 / 跟踪 / 持有”，默认“关注”，之后可以修改。三者位于同一关注股票列表，使用同一研究流程；标签不代表系统买卖建议，也不触发成本、数量或仓位管理。

关注标签只表达用户与股票的关系。其他普通标签只用于筛选列表和临时定位对象；两者都不创建研究项目、独立股票池或跨对象全局报告。

报告归属于具体对象，因此没有“报告”Tab。用户从对象卡进入对象页后查看当前报告。

## 3. Watch-list lifecycle

### 3.1 Placeholder

对象加入后立即出现在关注列表。初始化未完成时：

- 卡片保持正常对象身份和可点击入口；
- 默认不展示队列步骤、进度百分比或 Agent 内部状态；
- 点击后读取初始化事件：未完成时提示“正在建立研究”，完成时进入对象页。

### 3.2 Completion and failure

- 初始化完成后，卡片展示最近完成的研究状态和更新时间；
- 初始化自动重试三次；
- 三次失败后，对象保持在列表，点击提示已暂停并提供“恢复建立研究”；
- 恢复沿用原对象和已经成功形成的知识，不创建重复对象。

### 3.3 Unfollow

取消关注只移出当前列表并停止主动更新，不删除对象知识、报告或 Memory。再次关注时恢复原对象。

### 3.4 Delete research record

彻底删除是对象页“更多”中的低频破坏性动作，不与取消关注合并。确认界面必须明确说明：

- 将删除该对象的研究状态、当前报告、研究依据、Memory、关系和关注状态；
- 将停止该对象的持续更新；
- 用户上传的原始资料不会删除，只会解除对象关联；
- 删除后可以从“数据 → 配置 → 变更记录”恢复。

界面使用“研究档案”和“原始资料”，不出现 Wiki、Git、commit 或文件路径。用户二次确认后才调用确定性删除命令。

## 4. Recent updates

每个研究 Tab 顶部的“最近更新”按完成时间展示：

- 待复核；
- 研究状态变化；
- 当前报告更新；
- 复核后结论不变，包括每周轻复核的「查过了，没变」；
- 缺少定期报告导致的证据过时；
- 需要用户处理的失败。

对象卡同步显示未查看标记。研究变化同时复用现有关注股票公告 / 新闻消息聚合能力，不新建另一套通知中心，也不做外部消息推送接口。用户进入对象页后可以定位本次变化的原因和证据；“结论不变”也必须说明检查了什么，而不能只报完成。

## 5. Object-page skeleton

个股和行业面向所有 A 股投资者使用同一已确认骨架：

```text
研究状态
→ 实时指标
→ 当前报告
→ 研究依据
→ 关系跳转
→ 助手
```

### 5.1 Research state

| 状态 | 用户含义 |
|---|---|
| 绿 | 条件总体有利 |
| 黄 | 关键指标分化 |
| 红 | 条件明显恶化 |
| 灰 | 证据不足，暂无法判断 |

状态不是评分。状态区必须允许用户展开查看：

- 主要原因；
- 对应证据及 FCISU；
- 数据截至时间与时效；
- 当前冲突或缺口；
- 改变判断的条件。

### 5.2 Real-time indicators

实时指标从接口按需读取，不持久化 tick。个股至少需要覆盖当前价格与日 K、财务与估值、利润关键变量及适用的行业先行指标；行业需要覆盖价格、价差、供需、库存、订单、景气或产业链指标。不同产业按方法框架选择真实有效的指标，不套通用指标清单。

每个指标块表达数值、口径、日 / 周等变化、数据日期和来源。当前价格可以与最近完成的价值区间确定性计算估值位置和安全边际；价格或其他指标越过关键阈值时产生“待复核”，但只有完成分析后才能改变研究状态、利润假设或价值区间。

### 5.3 Current report

每个对象只有一份持续更新的当前报告。报告至少包含：

1. 当前判断和研究状态；
2. 业务模型或行业机制；
3. 收入、成本、利润、现金流的拆分方法与当前结果；
4. 关键先行指标及其最新变化；
5. 财务 / 估值模型、关键事实与假设；
6. 价值区间、当前价格、估值位置和安全边际；
7. 风险、证伪条件和证据缺口；
8. 关键陈述的证据锚点。

报告中的业务模型、收入成本与利润拆分部分优先以结构化 Dashboard 呈现（占比可视化、紧凑表格、观察点卡片），避免长文本罗列。

初始化允许生成稀疏报告，但必须显式表达缺口。报告更新失败时保留最后成功结果并显示失败状态。

报告可导出或回灌为新资料。产品不提供报告版本列表、版本号、基线或回滚界面；知识仓库的变更恢复不等同于报告版本产品。

### 5.4 Research evidence

界面名称使用“研究依据”，不要求用户理解 Wiki。内容按业务含义组织为对象档案、事实、关系和缺口；关键陈述可以展开证据锚点并回到原文。

### 5.5 Relations

个股对象至少展示主行业关系，行业对象展示关联重点个股。关系跳转保留当前对象身份，不创建新的研究项目。

## 6. Review rhythm and triggers

复核分轻、深两级。轻复核按固定时间发生，深复核由事件驱动。时间负责保证不漏，事件负责决定何时重算。系统主动获取新资料的调度由 [`../data-design/data_design.md`](../data-design/data_design.md) 拥有；本节只定义拿到资料之后如何复核。

### 6.1 轻复核（周节拍）

每个关注对象每周执行一次轻复核，检查：

- 实时指标和先行指标是否越过关键阈值；
- 当前价格相对最近完成的价值区间的位置和安全边际；
- 是否存在已摄取但尚未进入分析的新资料。

轻复核只有两种结果：「复核后结论不变」，或标记「待复核」。它不重算利润假设、不重算价值区间、不重写当前报告、不改变研究状态。结果进入「最近更新」，并说明本次检查了什么范围、数据截至何时；「结论不变」不能只报完成。

### 6.2 深复核（披露节拍与事件）

深复核重算利润拆分、财务模型、价值区间、研究状态和当前报告。以下情况触发：

- 对象首次初始化；
- 该对象的定期报告（季报、半年报、年报）实际摄取完成；
- 重大公告或行业事件影响关键利润变量；
- 实时指标越过 Schema / Skill 声明的关键阈值，且已被标记待复核；
- Wiki 出现实质新事实，或已有冲突得到解决；
- 用户主动要求复核，或确认采用持续假设。

定期报告以资料实际到位为准，不按日历季度。日历上的季度末本身不构成复核条件：此时报告尚未披露，重算只会用与上一期相同的输入得到相同结论。

### 6.3 缺报兜底

超过某报告期的法定披露截止日与宽限期，仍未摄取到该对象的定期报告时，系统不执行深复核，而是：

- 把该对象的财务证据标记为过时；
- 在「最近更新」中明确说明缺少哪一期报告；
- 将其登记为知识缺口；
- 证据已不足以支撑现有判断时，研究状态转为灰。

系统不因为「到时间了」就用旧输入重算一遍并宣称已复核。

### 6.4 价格与复核的关系

实时价格基于最近完成的价值区间更新估值位置和安全边际，不触发复核，也不重写报告。价格越过关键估值阈值时标记待复核；只有完成深复核后，才更新研究状态、价值区间和当前报告，并写入最近更新。

## 7. Methods and Skills

### 7.1 Default spine

默认分析主线固定为：

```text
业务 / 行业机制
→ 收入、成本与利润拆分
→ 财务模型
→ 关键先行指标
→ 实时数据替换滞后信息
→ 利润趋势与现金流
→ 适用估值模型与价值区间
→ 当前价格、估值位置与安全边际
→ 证伪条件
```

### 7.2 Runtime composition

运行时按以下优先级组合：

1. 默认主线提供不可绕过的证据和风险底线；
2. 财报量化、利润拆分、现金流验证、关键指标发现、估值和证伪等通用方法增强具体环节；
3. 当前对象的 Purpose、Schema、个股 / 行业 Wiki 和 Memory 提供已经形成的上下文；
4. 用户方法补充，或明确替换指定环节。

首版不要求行业专用 Skill。Agent 使用通用方法从对象资料中动态发现关键变量和补料方向；稳定方法可以在多次验证后再沉淀复用。通用方法和 Agent 动态发现规则以 [`analysis_frameworks.md`](analysis_frameworks.md) 为实施参考。

现有方法中的买卖点、仓位和阈值必须转换为研究条件、复核触发和状态原因，不直接输出交易指令。

### 7.3 Skill interface

研究模块消费已经启用、适用范围匹配的 Pi Skills。配置和导入由数据模块负责。Skills 主要承载通用分析与 Wiki 维护过程，不要求按行业穷举。研究模块在报告中记录本次实际使用的方法和数据时间，但不向用户暴露运行时装载细节。

## 8. Valuation

估值不是通用 PE / ROE 卡片的重复展示，也不能脱离利润模型只给倍数。当前报告应按对象和行业选择合适方法，将业务与行业变量映射到利润和价值区间，并表达：

- 方法及适用原因；
- 事实输入和模型假设的区别；
- 价值区间、当前市场价格、估值位置、安全边际和吸引力；
- 高估、合理、低估或证据不足的原因；
- 对利润驱动和关键先行指标的敏感性；
- 数据时间、证据强度和失效条件。

产品不输出明确买卖、目标操作点位或仓位建议。

### 8.1 Structured scenario flow

当用户提出“如果运价下降 20%”“换一个增速假设”等情景时：

```text
助手识别估值意图
→ 调用结构化估值输入 Tool
→ 前端展示默认值、可编辑项、口径和来源
→ 用户确认
→ 确定性估值函数重算
→ 助手解释变化
```

本次情景默认不修改当前报告。用户选择“采用为持续假设”时，前端再次展示影响并确认；确认后写入对象 Memory 并触发复核。

## 9. Assistant contract

### 9.1 Session

- 助手入口存在于所有页面；本模块负责研究页面的上下文合同。
- 页面切换或刷新后开始空白对话，不维护对象会话历史。
- 同一路由内改变筛选条件不清空对话，但后续回答使用更新后的页面上下文。
- 完整聊天不持久化；长期价值内容进入对象 `wiki/memory.md`。

### 9.2 Deterministic context

个股研究页装载：个股 Wiki、对象 Memory、关联行业 Wiki、启用 Skills 和页面数据快照。

行业研究页装载：行业 Wiki、对象 Memory、启用的通用 Skills 和页面数据快照。

最新或大体量数据通过工具按需读取。助手结合用户当前问题和本轮对话评估所需解释深度，自行调整术语、背景说明和分析展开方式，不使用固定回答模板。关键判断仍需表达依据与证据强度、缺口和不确定性，以及改变判断的条件。

### 9.3 Structured actions

查询、取数和临时计算可直接执行。用户通过对话明确要求修改资料、Memory、持续假设或当前研究时，必须由 Tool 返回前端可解析的输入和影响摘要，用户确认后再调用确定性领域命令。

每轮回答后的有效 Memory 提取属于已经启用的自动维护，不逐轮请求确认；普通问答不得写入。Agent 不直接模拟界面操作，也不能绕过确认执行用户发起的持久修改。

## 10. Public interfaces

研究模块至少消费以下业务输入：

- 关注对象已创建 / 已取消 / 关注标签已修改；
- 初始化完成 / 暂停失败；
- 周节拍到期；
- 该对象的定期报告已摄取；
- 该报告期披露截止日与宽限期已过但报告未到位；
- Wiki 实质更新；
- 关键指标越阈；
- 用户要求复核；
- 用户确认采用持续假设；
- 用户确认删除研究档案 / 恢复研究档案。

研究模块至少产生以下业务结果：

- 待复核；
- 轻复核完成且结论不变；
- 深复核完成且状态变化；
- 深复核完成且结论不变；
- 缺少定期报告形成的知识缺口和证据过时标记；
- 当前报告更新 / 更新失败；
- 最近更新条目和现有消息聚合条目；
- Memory 候选及确认后的持续假设；
- 研究档案已删除 / 删除失败 / 已恢复。

具体事件名和 payload 在实施 Task 中定义，但必须保持上述用户可见语义。

## 11. Failure semantics

- 单个实时工具失败：对应指标显示最后成功时间和过期状态，其余对象页继续可用。
- 证据不足：状态为灰并列出缺口，不把工具失败错误映射为红色研究状态。
- 报告更新失败：保留最后成功报告，提供重试。
- 助手工具失败：明确缺失数据和影响，不补写无来源结论。
- 结构化动作取消：不产生持久修改，也不写成功日志。
- 结构化动作执行失败：保持原状态，展示失败和重试入口。
- 删除研究档案失败：对象、关注状态和最后成功研究全部保持不变，不能出现半删除。

## 12. Business validation

研究模块完成首版验收时必须证明：

- 行业 / 个股两个 Tab 能容纳占位、完成、待复核和恢复对象；
- 个股可以在同一列表选择和修改关注 / 跟踪 / 持有标签，不生成独立股票池或持仓表单；
- 对象页按统一骨架展示，并能在个股和主行业之间双向跳转；
- 助手可以根据用户问题调整解释深度，但不会改变页面结构或降低证据要求；
- 四态研究状态均有可展开原因和证据，不随实时价格机械变化；当前价格变化能基于最近价值区间更新估值位置和安全边际；
- 系统可以在用户不提供分析方法的情况下，建立业务 / 行业框架、利润拆分、关键先行指标和初始估值方法；
- 每个对象只有一个当前报告，更新失败不会清空旧报告；
- 轻复核按周节拍自动发生，能表达“查过了，没变”并说明检查范围，且不重写报告或改变研究状态；
- 深复核由定期报告实际到位或重大事件触发，不按日历季度用旧输入空转；
- 定期报告逾期未到位时，系统标记证据过时并说明缺哪一期，而不是伪装已复核；
- 复核结果能表达“改变”和“不变”，并进入已有消息聚合；
- 页面刷新后聊天清空，但确定性 Wiki、Memory 和 Skills 能重新建立上下文；
- 估值情景通过结构化输入和二次确认完成，不要求预制通用参数面板；
- 删除研究档案能够明确区分删除内容与保留的用户资料，并可从变更记录恢复。
