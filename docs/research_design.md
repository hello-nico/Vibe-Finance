# 研究模块设计

> 状态：已确认的产品方向。本文是研究模块的业务设计来源；具体字段、证据强度、任务状态和接口仍待形成 Module Contract 与 Task。

## 1. 核心结论

研究模块没有预先存在的“话题”或“专题”。用户先从公司或行业详情页加入一个研究对象，该对象进入**研究池**；用户随后用自己的标签组织对象和资料，相同标签自然形成可分析的研究集合。

```text
行情发现
→ 公司 / 行业详情
→ 加入研究
→ 进入研究池的“未分组”
→ 后台整理资料并发现业务联系
→ 用户添加标签、加入更多对象、上传资料
→ 相同标签形成研究集合
→ 选择分析模板
→ 生成综合分析 Dashboard
→ 新资料驱动增量更新和下一版报告
```

公司和行业已有独立详情页，研究页不重复展示单体行情、财务和基础资料。研究页的价值是把多个对象与用户资料放在一起，分析产业链、竞争格局、客户供应商和上下游传导。

用户界面使用研究池、标签、研究集合、研究资料、产业链、竞争格局、关联公司和分析报告等金融投研语言。Wiki、Graph、Claim、Ingest 仅为内部实现概念。

## 2. 研究对象与研究集合

### 2.1 公司和行业

`company` 与 `industry` 是后台长期维护的两个核心对象：

- 公司详情页提供单个公司的行情、财务、估值、公告和基础资料；
- 行业详情页提供单个行业的行情表现、产业结构、景气数据和重点公司；
- “加入研究”只出现在这两类详情页；
- 行情页负责发现，不直接加入研究。

### 2.2 研究池

研究池承接所有用户已经加入、但尚未形成分析范围的公司和行业。它始终提供：

- **全部研究**：所有已加入对象；
- **未分组**：尚未添加用户标签的对象；
- **用户标签**：按用户定义的研究方向筛选对象和资料。

“加入研究”首先表示进入研究池并启动后台整理，不要求用户提前创建专题、填写长表单或选择完整研究方法。

### 2.3 标签集合

标签是用户定义研究边界的方式。相同标签下的公司、行业和资料构成一个研究集合，例如：

```text
人形机器人
├─ 人形机器人行业
├─ 绿的谐波
├─ 三花智控
├─ 拓普集团
├─ 电话会议纪要
└─ 券商产业链报告
```

规则：

- 同一对象或资料可以有多个标签；
- 标签先用于组织，只有用户发起分析后才产生 Dashboard；
- 系统可以推荐标签，但不能未经用户确认自动改变研究范围；
- 新识别出的关联公司只作为建议，不自动进入研究池或标签集合。

## 3. 第一次加入后的业务状态

### 3.1 空研究页

用户尚未加入任何对象时，研究页只说明一条明确路径：

```text
尚未加入研究对象
请先从行情进入公司或行业详情页，再点击“加入研究”。
```

研究页不提供另一套全市场搜索入口。

### 3.2 加入一个公司

例如用户加入“绿的谐波”，它首先进入：

```text
全部研究 / 未分组 / 绿的谐波
```

页面不重复公司详情，而显示**研究准备状态**：

- 后台资料整理进度；
- 已识别的所属行业和产业链位置；
- 客户、供应商、竞争对手、可比公司和上下游发现；
- 已获取的财报、公告、研报和新闻；
- 待核实或相互冲突的信息；
- 添加标签、上传资料、加入关联对象等下一步操作。

### 3.3 加入一个行业

例如用户加入“人形机器人”，它同样进入未分组。研究准备状态重点显示：

- 初步产业链环节；
- 各环节发现的代表公司；
- 供需、技术路线和景气资料；
- 竞争格局与上下游传导线索；
- 可加入研究池的公司建议；
- 当前资料缺口。

### 3.4 初始页面示意

```text
绿的谐波                         资料整理中

已识别
- 所属方向：人形机器人
- 产业链位置：谐波减速器
- 发现 6 家关联公司
- 已整理 3 份财报、12 条公告
- 暂无用户资料

下一步
[添加标签] [查看关联公司] [上传资料]
```

此阶段没有综合 Dashboard。它解决的是“系统已经知道什么、发现了谁、用户下一步如何形成研究范围”。

## 4. 后台初始化任务

对象加入研究池后，后台至少执行：

1. 确认公司或行业身份，避免同名和代码歧义；
2. 读取详情页已有的结构化金融数据；
3. 建立或增量更新公司、行业的长期研究资料；
4. 获取并整理公告、财报、研报、新闻等可用资料；
5. 识别行业—公司和公司—公司的直接业务联系；
6. 为识别结果绑定来源、时间和核实状态；
7. 生成标签建议、关联对象建议和资料缺口；
8. 将任务进度和失败原因返回研究页。

按钮和任务状态建议为：

```text
加入研究
→ 资料整理中
→ 待分组
→ 已加入研究
```

生成报告是标签集合上的后续动作，不应成为单个对象加入研究后的必经状态。

## 5. 业务联系

业务联系是后台增量维护和集合分析的核心。

### 5.1 行业与公司

- 公司属于或参与哪些行业；
- 公司位于哪个产业链环节；
- 公司提供什么产品或服务；
- 公司是供应方、需求方、核心参与者还是外围参与者；
- 公司在特定标签集合中的研究角色。

### 5.2 公司与公司

- 客户与供应商；
- 上下游；
- 竞争对手与可比公司；
- 合作伙伴；
- 股权、投资或控制联系。

### 5.3 准入原则

每项业务联系至少需要具体业务内容、信息来源、确认时间和当前状态。共同出现在一篇资料中不能自动构成业务联系。

系统应区分：

- 可跨标签集合复用的客观业务事实；
- 仅在某个研究范围下成立的角色、观点或影响判断。

新资料与已有记录冲突时不静默覆盖；保留旧版本、展示冲突并等待核实。

## 6. 用户资料与增量更新

用户可以上传：

- 年报、季报和财务资料；
- 电话会议、业绩会和闭门会议纪要；
- 公司公告和投资者问答；
- 券商研报和行业材料；
- 用户笔记、表格和自有数据；
- 新闻、政策文件和外部检索结果。

资料先进入研究池，再由用户添加一个或多个标签。底层借鉴 `llm_wiki` 的 Schema、两阶段导入、页面合并、链接、搜索和增量更新流程：

```text
上传原始资料
→ 识别资料类型、时间、公司和行业
→ 提取新增事实、观点、风险和业务联系
→ 与已有资料去重和比较
→ 标出新增、更新、冲突与待核实内容
→ 更新相关公司 / 行业的后台研究资料
→ 更新对应标签集合的研究上下文
→ 提示是否重新分析
```

原始文件始终保留。短期行情、传闻和模型推断不能直接改写长期资料。

## 7. 从标签集合到 Dashboard

用户选择一个标签后，可以查看该集合当前包含的对象和资料，并发起综合分析。

### 7.1 分析前

集合页先展示：

- 已加入的公司和行业；
- 每个对象在集合中的角色；
- 用户资料及其处理状态；
- 已确认和待核实的业务联系；
- 资料覆盖和明显缺口；
- 推荐的分析模板。

### 7.2 分析模板

模板决定研究问题、所需数据、计算方式和 Dashboard 结构，而不只是报告排版。第一批候选模板：

- 产业链拆解；
- 供应链分析；
- 竞争格局分析；
- 多公司横向比较；
- 财报与经营跟踪；
- 事件影响分析；
- 上下游传导分析；
- 周期与景气跟踪。

一次分析只设一个主模板，必要时加入少量辅助分析。宏观和热点不作为独立研究类型，只在与当前标签集合相关时作为分析输入。

### 7.3 分析后

Dashboard 至少回答：

- 本次分析的核心结论；
- 集合内重点公司及其角色；
- 产业链、竞争格局和关键业务联系；
- 关键金融数据和多对象比较；
- 最新资料相对上一版带来的变化；
- 主要风险、分歧和资料缺口；
- 本次实际使用的资料、数据时间和限制。

历史报告保留当时输入和结论，不被下一版覆盖。

## 8. 研究页状态与布局

研究页必须先按业务状态变化，而不是始终展示同一 Dashboard。

### 8.1 状态一：空研究池

引导用户从公司或行业详情页加入研究。

### 8.2 状态二：未分组 / 研究准备

```text
左侧：全部研究、未分组、用户标签
中间：当前对象的整理进度、关联发现和资料缺口
右侧：添加标签、上传资料、查看任务和加入关联对象
```

### 8.3 状态三：标签集合 / 分析准备

```text
左侧：用户标签
中间：集合成员、业务联系、资料覆盖和模板建议
右侧：上传资料、调整范围、选择模板和发起分析
```

### 8.4 状态四：报告 Dashboard

```text
左侧：用户标签与历史报告
中间：当前集合的最新 Dashboard
右侧：研究资料、运行状态、来源和继续追问
```

## 9. 持续研究闭环

```text
加入公司 / 行业
→ 进入研究池并整理资料
→ 用户用标签形成集合
→ 上传资料和加入更多对象
→ 生成综合分析 Dashboard
→ 新资料增量更新后台研究资料和业务联系
→ 标记相对上一版的变化
→ 用户重新分析
→ 保留历史报告并生成下一版
```

“加入研究”不是收藏；“标签”不是装饰；“上传资料”不是附件管理。三者共同决定系统持续研究什么。

## 10. 第一版边界

第一版优先跑通：

1. 从公司或行业详情页加入研究池；
2. 空研究池、未分组、标签集合和 Dashboard 四种状态；
3. 用户为公司、行业和资料添加标签；
4. 相同标签形成可分析集合；
5. 识别直接行业—公司、公司—公司业务联系；
6. 上传资料后增量更新，不覆盖原文和历史报告；
7. 选择一个内置模板生成基础 Dashboard；
8. 新资料进入后提示重新分析并生成下一版。

第一版不做：

- 预先要求用户创建专题；
- 独立宏观研究或热点研究对象；
- 从研究页承担全市场发现；
- 自动把所有关联公司加入研究池；
- 无来源支持的业务联系；
- 默认生成旗舰级长篇交互网站；
- 买卖建议、目标价和统一技术评分。
