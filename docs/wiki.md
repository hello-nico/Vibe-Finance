# 后台研究知识设计

> 用户可见的业务流程与术语以 [`research_design.md`](research_design.md) 为准。本文件只说明后台长期资料的职责。

- `company` 和 `industry` 是后台长期维护的两个核心对象，保存当前可复用的公司与行业资料。
- 公司、行业已有独立详情页；研究页不再按这两类对象重复组织内容。
- 后台重点维护行业—公司和公司—公司的业务联系，包括产业链位置、客户供应商、上下游、竞争合作及股权投资联系。
- 每项业务联系需要具体业务内容、来源、确认时间和当前状态；共同出现在同一资料中不能自动构成联系。
- 用户加入的公司和行业先进入研究池；相同用户标签下的对象和资料形成可分析的研究集合，不要求预先创建专题。
- 用户上传年报、财报、电话会议、闭门会议、研报、笔记或表格后，系统先识别涉及对象与新增信息，再与现有资料去重、比较和增量合并。
- 一次导入可以更新标签集合的研究上下文；有充分来源支持的稳定信息还可以更新对应公司或行业资料。
- 分析报告是有时间边界的结果，保留当时输入和结论，不覆盖历史；标签集合完成分析后展示最新 Dashboard。
- 宏观和热点不作为独立研究对象，只在与当前研究集合相关时作为分析输入。
- 底层可复用 `llm_wiki` 的 Schema、两阶段导入、Markdown 合并、链接、搜索和版本更新能力，但用户界面使用研究池、标签、研究集合、产业链、竞争格局、关联公司和研究资料等金融术语。
